Integridad de Peticiones (Sandra Server)

Sandra Server provee protección mediante X-Signature y X-Timestamp en sus cabeceras. Esta arquitectura asegura que el contenido de las peticiones no sea manipulado por intermediarios.

Implementación Criptográfica en Angular

El siguiente código muestra la generación de la firma HMAC utilizando la API Web Crypto:

public async hmac(message: string, key: string): Promise<string> {
  const encoder = new TextEncoder();
  const keyData = encoder.encode(key);
  const messageData = encoder.encode(message);

  // Importar la llave para HMAC
  const cryptoKey = await crypto.subtle.importKey(
    'raw',
    keyData,
    { name: 'HMAC', hash: 'SHA-256' },
    false,
    ['sign']
  );

  // Firmar el mensaje
  const signature = await crypto.subtle.sign(
    'HMAC',
    cryptoKey,
    messageData
  );

  // Convertir el buffer resultante a Hexadecimal
  return Array.from(new Uint8Array(signature))
    .map(b => b.toString(16).padStart(2, '0'))
    .join('');
}

Automatización mediante HttpInterceptor

Para garantizar que todas las peticiones de escritura (POST, PUT, DELETE) estén firmadas sin modificar cada servicio individualmente, se implementa un HttpInterceptor. Este componente intercepta el tráfico saliente, calcula la firma y anexa las cabeceras de seguridad automáticamente. 

intercept(req: HttpRequest<any>, next: HttpHandler): Observable<HttpEvent<any>> {

    // Ignoramos peticiones GET o sin cuerpo, ya que no modifican estado crítico
    if (!req.body || req.method === 'GET') {
      return this.procesarPeticion(req, next);
    }

    // Generamos la marca de tiempo actual
    const timestamp = new Date().getTime().toString();
    
    // Concatenamos el cuerpo JSON con el timestamp para firmar el conjunto
    const payload = JSON.stringify(req.body) + timestamp;

    // Usamos 'from' para manejar la promesa del HMAC dentro del flujo reactivo
    return from(this.sha256.hmac(payload, this.SECRET_KEY)).pipe(
      switchMap(signature => {
        // Clonamos la petición inmutable agregando las cabeceras de seguridad
        const secureReq = req.clone({
          setHeaders: {
            'Web-Api-Key': this.API_KEY,
            'X-Signature': signature,
            'X-Timestamp': timestamp
          }
        });

        return this.procesarPeticion(secureReq, next);
      })
    );
}

Análisis de Seguridad Ofensiva y Cumplimiento Normativo

La implementación de firmas HMAC y Timestamps no solo protege contra ataques técnicos, sino que asegura el cumplimiento de estándares internacionales de seguridad como ISO/IEC 27001 y OWASP ASVS. Esta arquitectura de "Migas" protege el sistema frente a un atacante que utilice un Proxy de intercepción.

1. El Escenario de Intercepción

Cuando un atacante intercepta tu petición en Burp Suite, visualizará la siguiente estructura: 

Method: POST 

Headers:
Web-Api-Key: d166fde7..sse
X-Signature: d166fde7f848...
X-Timestamp: 1766671754376

Body:
{"funcion":"_SYS_LstAplicaciones", "parametros": ""}

Intento de Manipulación de Payload

Si el atacante modifica el cuerpo a: {"funcion":"_SYS_BorrarBaseDeDatos"} y presiona "Forward", se activa el siguiente protocolo de defensa:

Paso Acción del Sistema Detalle Técnico
1. Recepción El servidor Go recibe la petición interceptada con el payload modificado.
2. Extracción Se toma el nuevo body (BorrarBaseDeDatos) y el timestamp original del header.
3. Cálculo Go calcula su propia firma para los datos recibidos usando la SECRET_KEY interna.
4. Resultado La firma calculada es matemáticamente distinta a la X-Signature que generó Angular.
5. Acción Go detecta la discrepancia y rechaza la petición con un 403 Forbidden inmediatamente.

2. Mitigación de Ataques de Repetición (Replay Attacks)

Si el atacante no modifica el contenido, pero captura una petición válida (ej. Login) y la reenvía masivamente para saturar el sistema, entra en juego la validación temporal en Go.

Recomendación Final para Angular

Para maximizar la seguridad de la SECRET_KEY en el cliente:

  • No guardarla como una cadena simple estática.
  • Mejor práctica: Derivar la clave dinámicamente del token de sesión (sessionStorage.getItem('token')). De esta forma, la "llave" de firma es única para cada sesión de usuario y rota automáticamente al volver a iniciar sesión.
