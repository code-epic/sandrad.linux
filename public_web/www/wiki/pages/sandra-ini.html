Configuración Maestra: sandra.ini

El archivo sandra.ini constituye el manifiesto de configuración principal de la plataforma. Utiliza el formato estándar INI, caracterizado por su legibilidad y estructura en secciones ([seccion]) y pares clave = valor. Este archivo gobierna desde el arranque del daemon hasta la gestión de criptografía y conectividad.

Nota Técnica: Los cambios en este archivo requieren un reinicio del servicio para que el proceso en memoria (Heap) recargue las nuevas directivas.

1. Directivas Globales [globals]

Establece las reglas de negocio transversales y los mecanismos de seguridad perimetral del servidor.

Parámetro Valor Ejemplo Explicación Técnica y Cumplimiento
app_mode server Define la arquitectura de despliegue. server habilita los listeners de red, mientras que client configura el nodo para consumo pasivo.
rsa_signature true Habilita la firma digital dinámica. Utiliza pares de claves RSA (Pública/Privada) para garantizar la integridad y autenticidad de los tokens y comunicaciones internas.
Cumplimiento: ISO/IEC 27001 A.10.1.1 (Política sobre el uso de controles criptográficos).
tiempo_bloqueo 15 Establece la ventana de tiempo (en minutos) para el bloqueo temporal de cuentas tras detectar fuerza bruta.
Seguridad: Mitigación de ataques de diccionario según recomendaciones OWASP.
pool_conection 127.0.0.1 Define las direcciones IP autorizadas para el pool de conexiones o gestión administrativa, actuando como una Lista Blanca (Allowlist) a nivel de aplicación.
server_push true Activa el subsistema de notificaciones Web Push, integrando servicios de colas (RethinkDB) para entrega asíncrona.

2. Rutas del Sistema de Archivos [paths]

Define la topología de almacenamiento. Sandra Server sigue una estructura jerárquica para separar binarios, logs, archivos temporales y certificados.

Directiva Uso Crítico
base Raíz de la instalación. Punto de anclaje para rutas relativas.
signature Almacén de material criptográfico (certificados X.509 .crt y claves privadas .key).
Seguridad: Esta carpeta debe tener permisos estrictos (ej. chmod 700) en el sistema operativo.
temp Directorio para generación efímera (QR codes, PDFs). El sistema debe implementar rutinas de limpieza automática (Garbage Collection) en esta ruta.

3. Auditoría y Logs [log]

Configura el sistema de trazabilidad. El registro de eventos es fundamental para la forense digital y el monitoreo operativo.

Parámetro Descripción Normativa Asociada
system_log Registra errores críticos (PANIC, FATAL) y advertencias del kernel de la aplicación. ISO/IEC 27001 A.12.4
Registro y monitoreo: Se deben producir, mantener y revisar regularmente los registros de eventos de actividad del usuario, excepciones y eventos de seguridad.
query_log Auditoría de consultas a bases de datos. Crucial para detectar inyecciones SQL o accesos no autorizados a datos sensibles.
backup_log Expresión Cron (59 11 * * 5) para la rotación y archivado automático de logs. Garantiza la disponibilidad de espacio en disco.

4. Virtual Hosts y Enrutamiento [hosts]

Mapea dominios o subdominios a directorios físicos específicos, permitiendo que una sola instancia de Sandra Server aloje múltiples aplicaciones (Multi-tenancy). 

[hosts]
# Formato: subdominio.dominio = ruta_relativa
src.localhost = public_web/src
consola.localhost = public_web/consola
gdoc.localhost = public_web/www/gdoc

El servidor inspecciona la cabecera Host de la petición HTTP entrante para determinar qué aplicación servir.

5. Puertos y Cifrado TLS [ports]

Configura los listeners TCP y la terminación SSL/TLS. Sandra Server maneja nativamente HTTPS, requiriendo la ruta a los certificados.

Servicio Puerto Estándar Configuración TLS
App Principal 443 (HTTPS) Requiere https_app_cert y https_app_key. Habilita HTTP/2 automáticamente sobre TLS.
WebSockets (Chat) 8443 (WSS) Puerto dedicado para conexiones persistentes full-duplex. Segregarlo permite reglas de firewall específicas.
Desarrollo 2004 Puerto alternativo para pruebas o acceso a API de desarrollo sin exponer el puerto principal.

6. Integración PHP (CGI) [php]

Permite la ejecución de scripts PHP heredados o complementarios mediante CGI (Common Gateway Interface).

  • php_cgi: Ruta absoluta al binario ejecutable de PHP.
  • php_port: Puerto interno donde el proceso CGI escucha las peticiones reenviadas por Sandra.

# Configuracion inicial de Sandra Server
# @author Code Epic Technologies

[globals]
app_mode = server
crontab = true
server_php = true
server_dev = true
server_http = true
server_https = true
server_push = true
pool_conection = 127.0.0.1
other_paths = false 
banner = false
rsa_signature = true 
tiempo_bloqueo = 15

[paths]
base = /usr/local/bin/sandra
log = /usr/local/bin/sandra/log 
file = /usr/local/bin/sandra/file
temp = /usr/local/bin/sandra/tmp
signature = /usr/local/bin/sandra/signature
bin = /usr/local/bin/sandra/bin

[log]
system_log = true
cache_log = true
query_log = true
backup_log = 59 11 * * 5 
format_log = zip

[server]
protocol = https
name_dns = localhost

[hosts]
src.localhost = public_web/src
consola.localhost = public_web/consola
carlos.localhost = public_web/consola
gdoc.localhost = public_web/www/gdoc

[ports]
http_app = 80
https_app = 443
https_app_cert = signature/sandra.app.crt

https_chat = 8443
https_chat_cert = signature/sandra.app.crt
https_chat_key = signature/sandra.app.key

https_dev = 2004
https_dev_cert = signature/sandra.app.crt
https_dev_key = signature/sandra.app.key

php_include = /usr/include
