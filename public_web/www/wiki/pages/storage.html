Contenedor de Archivos

Use almacenamiento compatible S3 (MinIO) con políticas y object versioning. Indexación por metadatos y hash MD5/SHA256.

Un Bucket (cubo o contenedor) es un concepto fundamental en los servicios de almacenamiento de objetos en la nube (como AWS S3, Google Cloud Storage o Azure Blob Storage), y es el principal mecanismo utilizado para el control y la gestión de imágenes y otros archivos no estructurados. En esencia, un bucket es el contenedor lógico de nivel superior donde se guardan tus datos. Todo lo que subes (una imagen, un video, un documento) se conoce como objeto y debe estar contenido en un bucket

Sistema de Versionamiento "Sandra": Almacenamiento de Objetos con Git


El sistema "Sandra" reinventa la gestión de archivos e imágenes al fusionar la simplicidad del almacenamiento de objetos, similar a los buckets de S3, con el potente motor de versionamiento de Git. Cada contenedor de archivos en Sandra no es solo una carpeta, sino un repositorio Git completamente funcional, tratando cada archivo como un objeto versionado.


Este enfoque proporciona un control de cambios granular, un historial inmutable y la capacidad de trabajar con diferentes versiones de un archivo de manera concurrente, lo cual es ideal para escenarios como la edición de imágenes, la gestión de documentos de diseño o cualquier caso donde la trazabilidad y la recuperación de versiones anteriores sean cruciales.


Comparativa de Enfoques

Para entender mejor las ventajas, comparemos el método tradicional de almacenamiento en servidor con el enfoque de Sandra.

CaracterísticaSistema de Archivos TradicionalSistema "Sandra" (Basado en Git)
VersionamientoManual (ej: foto_v1.jpg, foto_final.jpg). Propenso a errores y desorden.Automático y atómico. Cada cambio genera un commit con un hash único (SHA-1).
HistorialInexistente o basado en logs de servidor. No se registran los cambios de contenido.Completo e inmutable. Se puede consultar el historial de cambios de cualquier archivo (git log).
IntegridadDepende de checksums manuales (MD5/SHA256).Garantizada por Git. Cada commit y objeto se verifica con su hash SHA-1.
ReversiónCompleja. Requiere tener copias de seguridad manuales de versiones anteriores.Sencilla. Se puede revertir a cualquier versión anterior usando su hash (git checkout).
Trabajo ConcurrenteDifícil. Se corre el riesgo de sobrescribir el trabajo de otros.Soportado a través de ramas (branches). Permite tener versiones "borrador" y "publicada" a la vez.

API Endpoints de Sandra

La interacción con los contenedores de archivos se realiza a través de una API RESTful que abstrae la complejidad de los comandos de Git.

EndpointMétodoDescripciónComando Git Equivalente
/v1/api/subirarchivosPOSTSube un nuevo archivo o una nueva versión de uno existente al contenedor. Esta acción crea un nuevo commit en el repositorio.git add <archivo> y git commit -m "..."
/v1/api/history/{id}GETObtiene el historial completo de versiones (commits) para un contenedor o archivo específico identificado por {id}.git log -- <id>
/v1/api/checkout/{id}/{hash}GETRecupera una versión específica de un archivo {id} correspondiente a un commit con un {hash} determinado.git checkout <hash> -- <id>
/v1/api/checkoutbranch/{id}/{branch}GETRecupera la última versión de un archivo {id} desde una rama (branch) específica (ej: main, desarrollo).git checkout <branch> -- <id>
