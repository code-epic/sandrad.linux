Subir y descargar archivos

Este manual detalla el uso del servicio de subida de archivos, incluyendo su implementación, los objetos clave involucrados, y ejemplos de cómo consumirlo desde diferentes lenguajes de programación.

1. Resumen del Servicio

El servicio de subida de archivos está diseñado para recibir uno o más archivos a través de una solicitud HTTP POST con multipart/form-data. La API procesa los archivos, los guarda en un directorio temporal y devuelve una respuesta en formato JSON.

2. Flujo de Subida de Archivos

A continuación, se presenta un diagrama de flujo que ilustra el proceso completo de subida de archivos, desde el cliente hasta el servidor. 

graph TD
      subgraph Cliente
          A[Selección de Archivo] --> B[Creación de FormData];
          B --> C[Envío de Solicitud HTTP POST];
      end
      subgraph Servidor API en Go
          C --> D{Manejo de Solicitud};
          D --> E{Validación de Token};
          E --> F[Parseo de `multipart/form-data`];
          F --> G[Creación de Directorio Temporal];
          G --> H1{Opción Git Activa?};
          H1 -- NO --> H[Iteración sobre Archivos];
          H1 -- SÍ --> I1[Inicializar/Cargar Repo Git go-git];
          I1 --> J1[Git: Añadir Archivos al Staging];
          J1 --> H; 
          H --> I[Apertura de Archivo];
          I --> J[Creación de Archivo en Servidor];
          J --> K[Copia de Contenido];
          K --> L1{Opción Git Activa?};
          L1 -- SÍ --> M1[Git: Commit con Log de Usuario];
          M1 --> L[Mapeo de Nombres de Archivo];
          L1 -- NO --> L;
          L --> N[Respuesta JSON];
      end
      N --> C[Respuesta del Servidor al Cliente];

3. Conceptos Clave

multipart/form-data

Es un tipo de contenido (Content-Type) que se utiliza en las solicitudes HTTP para enviar datos que no se pueden representar en un formato simple, como archivos binarios (imágenes, documentos, etc.) junto con datos de texto. El cliente empaqueta cada archivo y campo de texto en "partes" separadas dentro de la solicitud.

FormData (en JavaScript/Angular)

Es una interfaz que permite construir un conjunto de pares clave/valor para enviar datos a través de una solicitud HTTP, especialmente útil para enviar archivos. Es la contraparte del lado del cliente de multipart/form-data. Se pueden agregar campos con el método .append(), donde el primer argumento es la clave (por ejemplo, "archivos") y el segundo es el valor (el archivo en sí).

r.ParseMultipartForm(32 << 20) (en Golang)

Es la función en Go que procesa la solicitud multipart/form-data. El argumento 32 << 20 (que es equivalente a 32 MB) establece el límite de memoria que el servidor usará para almacenar los datos del formulario. Si el tamaño de la solicitud supera este límite, el resto se guardará temporalmente en el disco del servidor.

4. Implementación del Cliente

El cliente debe construir un objeto FormData y enviarlo al endpoint del servicio.

Objetos Clave y FormData

El servicio espera los siguientes campos en la solicitud FormData:

Campo Descripción Detallada Obligatorio Ejemplo de Valor
archivos Contiene el archivo o los archivos binarios a subir. Es fundamental que la clave del formulario coincida con la que espera el servidor (frm.File["archivos"]). En HTML, esto corresponde al atributo name de la etiqueta <input type="file">. Sí El contenido de un archivo seleccionado por el usuario.
identificador Una cadena de texto única que se utiliza para crear un directorio específico en el servidor. Esto permite organizar los archivos por usuario, sesión o transacción, evitando colisiones de nombres. Sí user-123, proyecto-alpha, sesion-xyz789
git Un campo opcional que, si se establece en "true", activa el sistema de versionamiento "Sandra". El servidor tratará el directorio del identificador como un repositorio Git, creando un commit por cada subida. Ideal para versionar imágenes, diseños o documentos. No true
return Un campo opcional que, si se establece en "true", modifica la respuesta del servidor. En lugar de un mensaje genérico, la API devolverá el nombre único del directorio creado, lo cual es útil para referencias futuras. No true


Ejemplo de FormData en Angular

El formulario HTML en el ejemplo del usuario ( form ) utiliza los nombres correctos (identificador y archivos). La función SubirArchivo en el componente de Angular crea el FormData directamente a partir de este formulario. 


async SubirArchivo(e, posicion) {
  // Crea un objeto FormData a partir de los elementos del formulario HTML
  var frm = new FormData(document.forms.namedItem("forma"));

  // Llama al servicio para enviar el FormData
  await this.apiService.EnviarArchivosProgress(frm).subscribe({
    // ...
  });
}

Este enfoque simplifica el proceso, ya que el navegador se encarga de empaquetar los campos del formulario, incluyendo el archivo, en un FormData listo para ser enviado.

5. Ejemplos de Subida de Archivos

A continuación, se muestran ejemplos de cómo consumir este servicio utilizando diferentes lenguajes de programación.

Ejemplo en Python (usando la librería requests)

Este ejemplo utiliza la librería requests, que es un estándar de facto para realizar solicitudes HTTP en Python. 

import requests
# URL del servicio
url = "http://localhost:8080/api/v1/subirarchivos"

# Ruta del archivo a subir
archivo_a_subir = "/ruta/a/tu/documento.pdf"

# Parámetros del formulario
datos = {
    'identificador': 'tu_identificador_unico'
}

# Abrir el archivo en modo binario
with open(archivo_a_subir, 'rb') as archivo:
    # Crear el diccionario de archivos para 'requests'
    # La clave 'archivos' debe coincidir con el nombre esperado por la API en Go
    archivos = {
        'archivos': (archivo_a_subir.split('/')[-1], archivo)
    }

    # Encabezados de la solicitud (incluyendo el token de autorización)
    headers = {
        'Authorization': 'Bearer TU_TOKEN_DE_ACCESO'
    }

    # Realizar la solicitud POST
    try:
        respuesta = requests.post(url, data=datos, files=archivos, headers=headers)

        # Imprimir la respuesta
        if respuesta.status_code == 200:
            print("Archivo subido exitosamente.")
            print("Respuesta del servidor:", respuesta.json())
        else:
            print(f"Error al subir el archivo. Código de estado: {respuesta.status_code}")
            print("Respuesta del servidor:", respuesta.text)

    except requests.exceptions.RequestException as e:
        print(f"Error de conexión: {e}")

Ejemplo en Flutter (usando la librería http)

Este ejemplo utiliza la librería http para realizar una solicitud multipart. 

import 'dart:io';
import 'package:http/http.dart' as http;

Future<void> subirArchivoFlutter(String filePath, String identificador, String token) async {
  var uri = Uri.parse('http://localhost:8080/api/v1/subirarchivos');

  // Crear una solicitud multipart
  var request = http.MultipartRequest('POST', uri)
    ..headers['Authorization'] = 'Bearer $token';

  // Añadir campos de texto
  request.fields['identificador'] = identificador;

  // Añadir el archivo
  // La clave 'archivos' debe coincidir con el nombre esperado por la API en Go
  request.files.add(
    await http.MultipartFile.fromPath(
      'archivos',
      filePath,
    ),
  );

  // Enviar la solicitud
  try {
    var response = await request.send();

    // Leer la respuesta
    if (response.statusCode == 200) {
      String responseBody = await response.stream.bytesToString();
      print('Archivo subido exitosamente: $responseBody');
    } else {
      print('Error al subir el archivo. Código de estado: ${response.statusCode}');
      String responseBody = await response.stream.bytesToString();
      print('Respuesta del servidor: $responseBody');
    }
  } catch (e) {
    print('Error de conexión: $e');
  }
}

// Ejemplo de uso:
// subirArchivoFlutter('/ruta/a/tu/documento.pdf', 'identificador123', 'TU_TOKEN_DE_ACCESO');

Ejemplo con cURL (desde la terminal)

cURL es una herramienta de línea de comandos muy útil para probar APIs. Este comando simula una solicitud multipart/form-data. 

curl -X POST \
      -H "Authorization: Bearer TU_TOKEN_DE_ACCESO" \
      -F "identificador=tu_identificador_unico" \
      -F "archivos=@/ruta/a/tu/documento.pdf" \
      http://localhost:8080/api/v1/subirarchivos

Explicación del comando curl:

  • -X POST: Especifica el método HTTP como POST.
  • -H "Authorization:...": Añade el encabezado de autorización.
  • -F "identificador=...": Añade el campo de formulario identificador.
  • -F "archivos=@...": Añade el campo de formulario archivos y especifica la ruta del archivo a subir. El @ le dice a curl que debe leer el contenido del archivo en la ruta especificada.
